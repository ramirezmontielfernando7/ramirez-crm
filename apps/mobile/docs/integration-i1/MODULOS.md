# Matriz de integración por módulo

Todas las rutas de esta tabla existen en la referencia 834806e; el inventario enlaza sus fuentes. «Sesión» significa Better Auth + ámbito/servicios, no que Mobile ya pueda autenticarse. Los permisos son los relevantes observados; delegaciones, módulos y permisos por verbo deben confirmarse en staging. Compatibilidad JSON no implica integración terminada.

| Módulo / orden | API real representativa | Auth/permisos | Datos/acciones y compatibilidad | Dependencias y riesgos |
|---|---|---|---|---|
| Acceso I2 | `/api/auth/[...all]`, `/api/account-link/[token]` | Better Auth; enlace de un uso con rate limit | login email, sesión/cierre; activación/reset administrativo | cookies/orígenes/Set-Cookie en Android/iOS por probar; plugin org bloqueado; sin correo de reset automático |
| Bandeja I3 | GET `/api/conversations`, `/counts`, `/unread` | sesión; scope/asignaciones/participación | lista paginada, búsquedas/filtros, subconjuntos | DTO distinto de demo; cursor mutable; campañas/grupos vistas aparte |
| Chat I3 | GET/POST `/api/conversations/[id]/messages`; POST `/messages/template`, `/messages/media`, `/messages/knowledge`; PATCH/DELETE `/api/conversations/[id]` | sesión + acceso; delete pide conversation.delete | mensajes, estado, leído/IA/archivado; JSON/multipart | historial sin paginación; ventana 24 h; envío real y cuota/terceros; sin clave idempotente |
| Tiempo real I3 | GET `/api/events` | sesión y audiencia | SSE efímero message.new/status, conversation.updated, asignaciones/handoff, etc. | adaptar lector nativo en primer plano; desconectar al fondo; no replay ni push |
| Contactos I4 | GET/POST `/api/contacts`; GET/PATCH `/api/contacts/[id]`; `/notes`, `/tags`, `/participants`, `/assignments`, `/timeline` | sesión; alcance; assignment.manage para gestión participantes/asignación | ficha, notas, etiquetas, historial; JSON | distinguir datos propios y privados Mi número; algunos GET inician descarga/reparación; conflictos concurrentes |
| Asignaciones I3/I4 | POST `/api/assignments`, `/api/assignments/bulk`; GET `/api/contacts/[id]/assignments` | assignment.manage al escribir; acceso al leer | cambio de responsable; lectura devuelve assignedUserId/assignedAt/history | pertenencia del asignado; invalidar acceso también en quien pierde el chat |
| Pipeline / oportunidades I4 | GET `/api/pipeline/board`, `/stages`; PATCH `/api/pipeline/leads/[id]` | sesión + alcance; pipeline.edit para administrar etapas | movimiento, motivo pérdida, monto/prioridad | mover lead propio no requiere permiso de administrar etapas; sin CAS/revisión de fila expuesta |
| Campañas I5 | `/api/campaigns`, `/preview`, `/[id]/send`, `/[id]/state`, `/[id]/recipients`, `/audiences/*`, `/metrics` | campaigns.manage + módulo | borradores, audiencia, lanzamiento/pausa y progreso | no llamar /send o /test sin autorización; cuotas Meta, consentimientos y estados; fuera de I1–I3 |
| Agenda I5 | `/api/bookings`, `/api/bookings/[id]`, `/api/calendar/availability`, `/api/calendar/settings` | sesión + alcance; settings.manage para configurar | citas, disponibilidad, configuración | zonas UTC/local, conflictos; Google/Zoom pueden causar acciones externas |
| Tareas / notas I5 | `/api/work/tasks`, `/api/work/tasks/[id]`, `/api/work/notes`, `/api/work/notes/[id]` | sesión; work.manage amplía alcance según servicio | CRUD de trabajo propio/equipo | no confundir notas internas con mensajes del cliente; permisos y conflictos |
| Equipo I5 | `/api/settings/team`, `/api/settings/team/[id]`, `/link`; `/api/team-chat/*` | users.read/users.manage; chat por audiencia y permisos team_chat | miembros, roles, enlaces y mensajes internos | contiene administración de acceso; no copiar SSE de chat común a chat privado |
| Estudio IA I5 | `/api/agent/profile`, `/api/lab/agents/*`, `/api/lab/runs`, `/api/lab/documents/*` | agent.manage y módulos | perfil, versiones/publicación, documentos y ejecución | publicación/ejecución/embeddings puede consumir recursos; no activar en esta fase |
| Asistente I5 | `/api/assistant/ask`, `/threads`, `/actions`, `/status` | assistant.use + módulo; owner según matriz actual | consultas y acciones asistidas | coste externo posible, streaming, alcance actual y confirmación de acciones |
| Ajustes I5 | `/api/preferences`, `/api/settings/appearance`, `/navigation`, `/branding`, `/messaging` | sesión; settings.manage en configuración organizativa | preferencias personales vs empresa | no propagar automáticamente colores/fuentes web al Mobile aprobado |
| Plantillas / rápidas I3/I5 | `/api/templates`, `/api/templates/sync`, `/api/quick-replies` | sesión; templates.manage para gestión | lectura de respuestas/plantillas; sincronización Meta separada | aprobaciones y ventana; /sync puede contactar proveedor; no ejecutado |
| Medios I3 | GET `/api/media/[assetId]`; POST `/api/conversations/[id]/messages/media` | sesión + alcance | lectura privada/subida multipart | tamaño/memoria, 410, MIME, cookie en Image, posible descarga externa bajo demanda |
| Uso / resultados I5 | `/api/usage/*`, `/api/number-health`, rutas analytics del inventario | usage.read, number_health.read, results.read según ruta | consumo, topes, salud y resultados | verificar datos observables por rol, evitar acciones de pago o relecturas Meta |
| Mi número / directa I5 separado | `/api/my-number/*`, `/api/settings/mi-numero/*`, `/api/conversations/[id]/mode` | dueño/audiencia, mi_numero.manage, direct_connection.* y módulos | datos privados/vinculación/modo | QR y conectores reales; jamás activar desde muestras; no concede acceso global scope.all |
| Push I6 | Sin endpoint móvil de registro/envío identificado | futuro usuario/org/instalación, autoridad de servidor | outbox y tokens propuestos | conservar T-M5A/B; credenciales/proveedor/envíos de prueba requieren autorización |
| Plataforma/bot/MCP | `/api/platform/*`, `/api/bot/*`, `/api/mcp`, `/api/oauth/*` | otros contextos/llaves/roles | APIs existen, NO son el adaptador Mobile normal | no usar llaves administrativas o del bot para simular login móvil |

No se implementan conexiones de estos módulos en I1. CrmReadPort/CrmActionPort son fronteras móviles propuestas: una proyección puede transformar una respuesta, no reproduce necesariamente su envoltorio JSON. `wire.ts` solo normaliza una selección de campos reales de conversaciones/mensajes y compone parámetros de consulta, sin ejecutar requests.
